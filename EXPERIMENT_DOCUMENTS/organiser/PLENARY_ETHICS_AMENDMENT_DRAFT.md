# Plenary Survey and Consent Amendment

**Implementation status: AI-attitude questions deployed in the formal survey templates on 2026-08-06. Ethics approval must be recorded before collecting plenary responses.**

This document records additions for the plenary experiment. The survey templates
contain the matched AI-attitude questions so the complete experiment can be
tested. Do not collect plenary responses until the relevant ethics amendment has
been approved and its reference is recorded here.

## Matched pre/post AI-attitude items

Use the same items before and after the experiment. Response scale:

1. Strongly disagree
2. Disagree
3. Neither agree nor disagree
4. Agree
5. Strongly agree

Proposed statements:

1. I trust an AI coding assistant to explain unfamiliar source code accurately.
2. I trust an AI coding assistant to propose suitable algorithms for a software task.
3. I trust an AI coding assistant to modify source code with limited supervision.
4. I trust an AI coding assistant to run development commands and tests safely.
5. I verify AI-generated code before treating a task as complete.
6. I prefer to retain direct control over implementation decisions when using AI.
7. I feel confident identifying when an AI coding assistant is mistaken.

Open response: **Please explain the main reasons for your ratings, including
the kinds of software-engineering work for which you would or would not rely on
an AI coding assistant.**

The post-experiment instrument should additionally ask: **Did this session
change any of your ratings? If so, what happened during the session that
changed them?**

## Optional anonymized-data-publication consent

Proposed separate, optional choice:

> I consent to the publication of de-identified research artifacts derived
> from my session, which may include prompts, code changes, command/test
> records, and short redacted screen-recording excerpts. I understand that the
> research team will review artifacts for direct identifiers and secrets before
> publication, and that declining this option does not affect participation in
> the study.

Provide distinct `Yes` and `No` choices. Do not bundle this with participation
consent, and do not publish raw material solely because general study consent
was provided.

## Ethics submission notes

- Explain the matched pre/post design and analysis of attitude change.
- State that ratings concern trust and control across different AI-assisted
  software-engineering activities.
- Describe the optional publication consent, de-identification process,
  withdrawal deadline, artifact review, and access controls.
- Update participant information, retention, and data-management documents.
- Record the approval reference before collecting responses with these survey
  templates.
